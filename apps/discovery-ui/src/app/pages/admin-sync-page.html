DStore container

How DSpace organizes repository data

DSpace (DStore) is the system of record. Public metadata sync writes Dublin Core and crr.* fields into items; bitstreams stay referenced, not mirrored, in this demo slice.

  1. Communities Top-level groupings such as Census Public Research Data.
  2. Collections Curated sets inside a community, for example TIGER/Line Geospatial Files.
  3. Items Research objects with metadata, relationships, and optional bitstreams.
  4. Metadata schema Dublin Core plus crr.program, crr.geography, crr.file.manifest, and related fields.

Seed and persistence flow

  • SAF seed package pnpm run dspace:seed imports communities, collections, and starter items idempotently.
  • Asset store Bitstreams live in the DSpace asset store; sync reconciles metadata and source links only.
  • DSpace PostgreSQL Repository state persists on dspace-postgres:5433, separate from application civics_ops on port 5432.

Discovery projection

How Solr serves public search

Solr is a rebuildable projection of DSpace. The discovery core on port 8983 powers keyword search, facets, and counts for the Angular UI. DSpace keeps its own internal Solr on port 8984 for repository-native search and OAI cores.

  1. Discovery Solr (:8983) Owned by repository-api; rebuilt from DSpace via Reindex discovery.
  2. DSpace Solr (:8984) Internal to DSpace; not queried directly by the public UI.
  3. Query path Discovery UI → repository-api → discovery core → typed SearchResponse.
